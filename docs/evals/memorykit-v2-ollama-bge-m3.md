# memorykit 检索评测：bge-m3（Ollama）

- 日期：2026-11-19
- 评测集：`project-memory-retrieval-v2`（36 条记忆、24 个查询），
  sha256 见 [`memorykit-v2-ollama-bge-m3.json`](memorykit-v2-ollama-bge-m3.json)
- 模型：Ollama `bge-m3`，1024 维，本机推理，无调用费用
- 路径：`examples/memory-embedding-eval`。记忆写入真实 PostgreSQL + pgvector
  （pgstore），由 `EmbeddingWorker` 生成向量，用生产代码 `Recaller` 召回，
  每个查询最多返回 4 条
- 复现：
  ```bash
  go run ./examples/memory-embedding-eval \
    --dsn 'postgres://...' --out docs/evals/memorykit-v2-ollama-bge-m3.json
  ```

## 结果

| 通道 | 向量阈值 | 召回 | 误召回 | 同义改写 | 英文 |
|---|---|---|---|---|---|
| exact + 全文（现状） | – | 19/22 | 1/30 | 1/4 | 4/4 |
| 仅向量 | 0.50 | 20/22 | 1/30 | 4/4 | 2/4 |
| **exact + 全文 + 向量** | **0.50–0.55** | **22/22** | **1/30** | **4/4** | **4/4** |
| exact + 全文 + 向量 | 0.60 | 21/22 | 1/30 | 3/4 | 4/4 |
| exact + 全文 + 向量 | 0.70 | 19/22 | 1/30 | 1/4 | 4/4 |
| exact + 全文 + 向量 | 0–0.40 | 22/22 | 2/30 | 4/4 | 4/4 |

所有组合都没有跨租户、跨项目、非 active 或过期的记忆被召回：唯一的误召回
`q-abstain-theme/m-noise-theme` 在作用域内，见下文。

延迟（本机）：查询向量化 p50 19.5ms / p95 21.4ms，含向量的一次召回
p50 21.6ms / p95 23.9ms。

## 结论

1. **向量通道补上了同义改写。** 三路融合、阈值 0.50–0.55 时，召回从 19/22
   提高到 22/22，同义改写从 1/4 提高到 4/4，误召回没有增加。只用向量不够：
   英文的两条（`q-en-sot`、`q-en-fallback`）相似度只有 0.49 和 0.45，要靠
   exact 和全文召回。三路融合才能都覆盖。
2. **向量挡不住 #9 的草稿主题误召回。** `m-noise-theme`（一条绿色主题的草稿）
   与"哪个 UI 主题已批准"的相似度是 0.584，比若干正确答案还高（`q-syn-closed`
   0.579、`q-en-sot` 0.49、`q-en-fallback` 0.445）。任何能把它挡在外面的
   阈值都会丢掉正确结果。区分"草稿"和"已批准"需要理解语义，靠宿主侧的
   reranker 或模型判断，相似度阈值做不到。
3. **bge-m3 的相似度整体偏高。** 无关记忆也常在 0.45–0.65 之间，有 3 个查询里
   某条无关记忆比正确答案还高（例如 `q-syn-intent`：正确 0.699，无关 0.76）。
   因此阈值应在 0.5 左右，再由 RRF 融合和条数预算来排序截断，不宜靠提高阈值
   去噪。阈值低于 0.5 时会多出一条误召回。
4. **全文通道的指标对 ID 敏感。** 全文命中词数相同时按记忆 ID 排序，在 4 条
   的预算边界上，正确答案能否入选取决于 ID 大小。用另一组 UUID 命名空间，
   fts-only 会从 16/22 变成 15/22（`q-life-db` 掉出）。词法评测固定的 16/22
   里有一条属于这种情况。

## 建议

- 用 bge-m3 时，`RecallPolicy.MinVectorSimilarity` 取 0.5，并打开三个通道。
- 换模型或评测集后重新跑本评测；不同模型的相似度分布差别很大，阈值不能沿用。
